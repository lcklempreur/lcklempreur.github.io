HAProxy : Reverse Proxy & Load Balancing

Objectif du projet

Mettre en place un reverse proxy (proxy inverse) avec HAProxy afin de répartir la charge (load balancing (répartition de charge)) entre deux serveurs web (Apache2 (serveur web)), tout en assurant un contrôle de disponibilité (health check (test d’état)).

Phrase récapitulative

"Mise en place d’un cluster web derrière HAProxy avec équilibrage Round Robin (répartition 50/50), supervision via page /stats et simulation de panne d’un backend."

Technologies et compétences mises en œuvre

  • Proxy : HAProxy (reverse proxy (proxy inverse))
  • Web : Apache2 (serveur web) sur Web1 et Web2
  • Équilibrage : Round Robin (répartition de charge 50/50)
  • Supervision : Interface HAProxy /stats (stats (statistiques de service))
  • Réseau : NAT (Network Address Translation), passerelle (gateway (routeur par défaut))
  • Sécurité : Auth basique (authentification (contrôle d’accès)) sur /stats
  • Optionnel : iptables (pare-feu Linux) + DNAT (Destination NAT) + MASQUERADE (SNAT dynamique)

Architecture (topologie)

L’infrastructure s’appuie sur un serveur HAProxy placé entre un réseau “WAN” (Internet (réseau public)) et un réseau “LAN” (réseau local).

  • HAProxy : WAN 192.168.43.240 / LAN 10.1.43.1
  • Web1 : 10.1.43.2 (Apache2)
  • Web2 : 10.1.43.3 (Apache2)
  • Client : réseau public 192.168.43.X

Mise en place (étapes clés)

  • Installation de HAProxy sur le serveur proxy (sans Apache2 sur cette machine).
  • Installation d’Apache2 sur Web1 et Web2.
  • Configuration HAProxy : frontend (point d’entrée) + backend (serveurs web) + checks.
  • Activation de la page de stats /stats (authentification (contrôle d’accès)).
  • Configuration de la passerelle (gateway (routeur par défaut)) sur Web1/Web2 vers HAProxy.
  • Tests : alternance Web1/Web2, simulation panne (arrêt Apache) et vérification bascule.

Extrait de configuration HAProxy (principe)

Exemple de bloc “listen” avec équilibrage Round Robin et supervision : 

listen cluster_web
  bind 192.168.43.240:80
  mode http
  balance roundrobin

  option httpclose
  option forwardfor

  server web1 10.1.43.2:80 check
  server web2 10.1.43.3:80 check

  stats enable
  stats hide-version
  stats refresh 30s
  stats show-node
  stats auth admin:admin
  stats uri /stats

Tests réalisés

  • Test HTTP : accès à l’IP HAProxy et rafraîchissement pour observer l’alternance Web1/Web2.
  • Test /stats : accès à http://IP_HAPROXY/stats pour vérifier l’état (UP/DOWN).
  • Test de panne : arrêt d’Apache2 sur Web1 puis vérification que Web2 prend le relais.

Difficultés techniques rencontrées

  • Service HAProxy ne démarre pas : erreur de syntaxe (configuration (fichier de conf)) ou mauvaise IP bind.
  • Conflit de port : Apache2 installé par erreur sur la machine HAProxy.
  • Routage : passerelle non définie sur Web1/Web2 (gateway incorrecte).

Résultats & bénéfices

  • Répartition de charge (load balancing (répartition de charge)) entre 2 serveurs.
  • Haute disponibilité “basique” (failover (bascule)) en cas de panne d’un backend.
  • Supervision simple via /stats et checks (health check (test d’état)).
